<interfaces>
The gzip magic-byte + DecompressionStream pattern from `config.ts` lines 39-46 (reproduced here for executor reference — DO NOT re-read config.ts, use this):

```typescript
// Check if response is still gzipped (server didn't set Content-Encoding).
// Gzip magic bytes: 1f 8b
const view = new Uint8Array(body);
if (view.length >= 2 && view[0] === 0x1f && view[1] === 0x8b) {
  const ds = new DecompressionStream("gzip");
  const writer = ds.writable.getWriter();
  writer.write(body);
  writer.close();
  body = await new Response(ds.readable).arrayBuffer();
}
```

The SW must replicate this logic in JavaScript (not TypeScript — SW files are plain JS).

`copy-assets.py` already mirrors `gendoc-template/javascripts/` → `site/javascripts/` post-build. The registration script placed in `javascripts/` will automatically be available at `/javascripts/search-gzip-register.js` in the built site. The Service Worker file must be at site root (`/search-gzip-sw.js`) for full scope — Plan 01's deploy.sh handles copying it there.

The MkDocs Material theme's search worker fetches `search_index.json` relative to the document base URL. The pattern to intercept is any fetch to a URL ending in `/search/search_index.json`.

The `extra_javascript` list in mkdocs.yml currently has 8 entries (lines 91-99). Regular scripts load synchronously before DOMContentLoaded, so the SW registration runs before the MkDocs search worker initializes. Add the registration script as a regular (non-module) script — place it last among regular scripts, before the module entry.

Create `gendoc-template/javascripts/search-gzip-sw.js` — a Service Worker that intercepts `search_index.json` fetches and transparently serves the `.json.gz` version with decompression. This file MUST be plain JavaScript (no TypeScript, no module syntax — Service Workers use the classic script context).

The SW must:

1. **Self-install on activate** — listen for `install` event and call `self.skipWaiting()`. Listen for `activate` event and call `self.clients.claim()`. This ensures the SW takes control immediately without waiting for a page reload.

2. **Intercept fetch events** — check if `event.request.url` includes `search_index.json`. If it does NOT, return (let the request pass through normally — do not call `event.respondWith` for non-matching URLs).

3. **Fetch .json.gz** — for matching requests, construct the `.gz` URL by appending `.gz` to the original URL. Fetch it with `{ cache: "no-cache" }` to avoid stale responses.

4. **Gzip detection and decompression** — replicate the `config.ts` lines 39-46 pattern in JavaScript:
   - Read the response as `arrayBuffer()`
   - Convert to `Uint8Array`
   - Check magic bytes: `view[0] === 0x1f && view[1] === 0x8b`
   - If gzipped, create `new DecompressionStream("gzip")`, write bytes via `ds.writable.getWriter()`, close writer, read decompressed via `new Response(ds.readable).arrayBuffer()`
   - If NOT gzipped (local dev fallback), use the body as-is — decode with `new TextDecoder().decode(bodyWithoutDecompression)`

5. **Return decompressed JSON** — create `new Response(decompressedBody, { headers: { "Content-Type": "application/json" } })` and pass it to `event.respondWith()`.

6. **Error handling** — if the `.gz` fetch fails (404 in local dev where deploy.sh hasn't run), fall back to fetching the original `.json` URL and return it as-is. Wrap all logic in try/catch and on error, fall through to the original request with `fetch(event.request)`.

The key identifiers used throughout: URL pattern `search_index.json`, URL construction by appending `.gz`, magic bytes `0x1f 0x8b`, `DecompressionStream("gzip")`, `Content-Type: application/json`.
