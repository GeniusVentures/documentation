**Design: Shared fetch-gzip.js wrapper**

Instead of per-consumer gzip logic or a Service Worker, one script intercepts `window.fetch` on the main thread. Any fetch to a URL ending in `.json` gets rewritten to `.json.gz` with transparent decompression. This is a build-time decision: `load-gendoc-config.py` reads `deploy.cloudflare.gzip_json` from gendoc.yml (default true) and injects the script into `extra_javascript` only when enabled.

When gzip_json is false: the wrapper never loads — zero interception overhead, no 404 round-trips, clean.

When gzip_json is true: the wrapper intercepts ALL .json fetches, rewrites to .json.gz, decompresses if gzipped. MkDocs search, Ask AI widget, and any future .json consumer all benefit from one file.

**Gzip magic-byte + DecompressionStream pattern** (from config.ts, lines 35-41 — reproduced here for executor reference):
```javascript
const view = new Uint8Array(body);
if (view.length >= 2 && view[0] === 0x1f && view[1] === 0x8b) {
  const ds = new DecompressionStream("gzip");
  const writer = ds.writable.getWriter();
  writer.write(body);
  writer.close();
  body = await new Response(ds.readable).arrayBuffer();
}
```

**URL matching**: Check `urlStr.split('?')[0].split('#')[0].endsWith('.json')` — match `.json` at end of path, not `.json.gz` or `.jsonp`. The wrapper only intercepts; it does NOT fall back. If `.json.gz` returns 404, the error propagates naturally (same as a missing `.json` would).

**config.ts simplification**: After the wrapper is in place, config.ts no longer needs:
- The `.json.gz` → `.json` fallback logic
- The gzip magic-byte detection + DecompressionStream
- The CONFIG_URL_FALLBACK constant
It just does `fetch("/ask-config.json", { cache: "no-cache" })` — the wrapper handles the rest.

**load-gendoc-config.py injection point**: The wrapper must load BEFORE any other script that calls fetch(). Insert at position 0 of `extra_javascript` so it runs first. The MkDocs Material bundle is auto-injected by the theme after all `extra_javascript` scripts, so ordering within extra_javascript ensures the wrapper is in place before the bundle makes its search_index.json fetch.

**copy-assets.py**: Already mirrors `gendoc-template/javascripts/` → `site/javascripts/` post-build. The new `fetch-gzip.js` placed in `javascripts/` will automatically be available at `/javascripts/fetch-gzip.js` in the built site — no changes to copy-assets.py needed.

This file MUST be plain JavaScript (no TypeScript, no module syntax — it runs as a classic script before any modules load).

The wrapper must:

1. **Save the original fetch** — `const _fetch = window.fetch.bind(window);`

2. **Replace window.fetch** — assign a new async function that:
   a. Resolves the URL string from the first argument (string, Request object, or URL)
   b. Strips query/hash: `urlStr.split('?')[0].split('#')[0]`
   c. Checks if path-only ends with `.json` — if NOT, pass through to `_fetch(url, options)`
   d. Constructs `.gz` URL: append `.gz` to the original URL
   e. Calls `_fetch(gzUrl, options)` — COMMITS, no fallback

3. **Gzip detection and decompression** — after fetching `.json.gz`, replicate the config.ts magic-byte + DecompressionStream pattern:
   - Read response as `arrayBuffer()`
   - Convert to `Uint8Array`
   - Check magic bytes: `view[0] === 0x1f && view[1] === 0x8b`
   - If gzipped, create `new DecompressionStream("gzip")`, write bytes, close writer, read decompressed via `new Response(ds.readable).arrayBuffer()`
   - If NOT gzipped (server set Content-Encoding), use body as-is

4. **Return decompressed Response** — `new Response(decompressedBody, { status: 200, headers: { "Content-Type": "application/json" } })`

5. **Wrap in IIFE** — `(function() { ... })();` to avoid polluting global scope.

6. **No fallback** — if the `.json.gz` fetch fails (404, network error), the error propagates naturally. The wrapper does not try `.json` as fallback.

The key identifiers: `_fetch` (original), `window.fetch` (replaced), URL matching via `endsWith('.json')`, magic bytes `0x1f 0x8b`, `DecompressionStream("gzip")`, `Content-Type: application/json`.
