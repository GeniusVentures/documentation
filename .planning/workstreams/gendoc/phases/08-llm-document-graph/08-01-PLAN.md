<objective>
Create `scripts/build-graph.py` — a build-time Python script that extends the existing `llms-meta.json` with LLM-generated document graph metadata. The script implements a two-pass LLM pipeline (evidence extraction then interpretation), section-level-first analysis, incremental reanalysis tied to content hashes, provider-agnostic API key detection (OpenAI + Anthropic per D-01), and silent skip when no API key is available (D-07). All prompts live inline (D-02).

Purpose: Transform the existing flat `llms-meta.json` into an enriched document graph with three-layer metadata (deterministic, computed, LLM-generated), provenance tracking on every inferred value, and five weighted relation types. This metadata powers enhanced search relevance, candidate ranking, and context ordering in the Ask AI worker.

Output: `gendoc-template/scripts/build-graph.py` — a self-contained Python script following the `build-llms.py` architectural pattern (SCRIPT_DIR/TEMPLATE_ROOT resolution, gendoc.yml config reading, same `scripts/` directory, same venv execution context).

## llms-meta.json Schema Extension (D-03)

Extend each entry under `meta["docs"][key]` with an optional `_graph` key:

```json
"_graph": {
  "provenance": {
    "model_id": "gpt-4o",
    "prompt_version": "v1",
    "analysis_date": "2026-07-24T00:00:00Z",
    "review_status": "raw"
  },
  "document_hash": "abc123...",
  "section_hashes": {
    "section:0": "hash1",
    "section:1": "hash2"
  },
  "summary": {
    "value": "one-sentence summary text",
    "origin": "ModelInferred",
    "confidence": 0.92
  },
  "questions_answered": [
    {
      "value": "How are bridge signatures aggregated?",
      "origin": "ModelInferred",
      "confidence": 0.91,
      "evidence": [{"section": "Overview", "start_char": 0, "end_char": 200, "quote_hash": "94ac72..."}]
    }
  ],
  "topics": [
    {"value": "cross-chain bridging", "origin": "ModelInferred", "confidence": 0.95}
  ],
  "entities": [
    {"value": "validator", "origin": "ModelInferred", "confidence": 0.97}
  ],
  "aliases": [
    {"value": "signature collection", "origin": "ModelInferred", "confidence": 0.88}
  ],
  "document_role": {
    "value": "architecture_specification",
    "origin": "ModelInferred",
    "confidence": 0.90
  },
  "authority_reason": "Is a normative standard describing system architecture",
  "authority_score": 0.90,
  "freshness_score": 0.85,
  "explicit_claims": [
    {"value": "claim text", "origin": "ModelInferred", "confidence": 0.89, "evidence": [...]}
  ],
  "relations": [
    {
      "type": "depends_on",
      "target": "other_doc_key_or_url",
      "weight": 0.92,
      "confidence": 0.88,
      "evidence": [{"section": "Section Name", "start_char": 100, "end_char": 300, "quote_hash": "..."}]
    }
  ]
}
```

All existing fields (hash, description, category, optional, exclude, nav_section, pinned, stale) remain unchanged. LLM-generated graph metadata is additive under `_graph`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Environment → Script | API keys are read from environment variables or parent .env file |
| Script → LLM API | Document content is sent to OpenAI/Anthropic APIs — untrusted response comes back |
| LLM API → llms-meta.json | LLM-generated content is written to a JSON file consumed by the worker at runtime |
| llms-meta.json → Worker (runtime) | Worker fetches this file and trusts its content for scoring |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Spoofing | LLM API endpoint | mitigate | Use HTTPS exclusively, validate response status codes, verify JSON parse succeeds before writing |
| T-08-02 | Tampering | llms-meta.json output | mitigate | Content hashes stored per section enable detection of unexpected content changes; graph metadata is additive (does not modify existing fields per D-03); stale flag on existing entries preserves editorial review status |
| T-08-03 | Repudiation | LLM analysis decisions | mitigate | Every inferred value carries model_id, prompt_version, analysis_date, review_status — full provenance chain for audit |
| T-08-04 | Information Disclosure | API key in error/logs | mitigate | Catch exceptions before API key appears in tracebacks; log only provider name, never key value; redact key from any error messages that include request details |
| T-08-05 | Denial of Service | LLM API rate limits | mitigate | Retry once on 429 with backoff; skip document on persistent failure; never fail the build for LLM errors; per-document analysis with individual error handling |
| T-08-06 | Elevation of Privilege | Malicious document content injected into LLM prompt | mitigate | Document content is from the gendoc pipeline (already trusted source); pass it as user message content (not system prompt); LLM output is parsed as JSON and validated before writing; no code execution from LLM output |
| T-08-07 | Information Disclosure | LLM prompt injection via document content | mitigate | Documents are from the project's own docs directory (gendoc pipeline, not user-submitted); section-level analysis limits context window per LLM call; Pass 2 uses only extracted facts (not raw document text) |
| T-08-SC | Tampering | Python pip packages (openai, anthropic SDKs if used, or requests) | accept | Script uses only stdlib urllib or existing requests dependency from build-llms.py pattern; no new pip packages added beyond what's already in requirements.txt; if SDKs are added, run Package Legitimacy Gate protocol |
</threat_model>
