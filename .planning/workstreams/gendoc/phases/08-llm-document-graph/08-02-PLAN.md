<objective>
Extend the Ask AI worker's TypeScript types, catalog loader, and scoring function to consume graph metadata from the enriched llms-meta.json produced by build-graph.py. This implements the worker-side integration of the LLM document graph (D-06), adding optional graph fields to CatalogEntry, fetching and merging llms-meta.json graph data during catalog loading, and enhancing scoreEntries with questions_answered matching, authority scoring, and graph-based ranking without replacing lexical retrieval (LLMGRAPH-05).

Purpose: The worker currently ranks documents using only title/description/URL term matching. With graph metadata, queries that match questions_answered fields get better results, high-authority documents get priority, and the composite relevance scoring formula R(d,q) from LLMGRAPH-05 is approximated in the worker's scoring function.

Output: Extended types.ts with GraphMetadata interfaces, enhanced catalog.ts with llms-meta.json fetching and graph-enriched scoring.
</objective>

|----------|-------------|
| llms-meta.json (CDN) to Worker fetch | Worker fetches llms-meta.json from origin — data is from build pipeline, not user input |
| Graph metadata to scoring function | Graph data from llms-meta.json flows into scoreEntries — must handle absent/corrupt data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-09 | Tampering | llms-meta.json fetched by worker | mitigate | Worker uses HTTPS fetch; JSON parse failures return gracefully (no crash); graph field is optional — absence of graph never breaks scoring |
| T-08-10 | Denial of Service | Large llms-meta.json fetch | mitigate | Metadata file is produced at build time and typically small (under 500 KB for corpus); fetch uses Cloudflare cache (cf cacheTtl as in existing fetchText pattern); cache lifetime matches CATALOG_TTL_MS |
| T-08-11 | Elevation of Privilege | Injected graph data in scoring | accept | Graph metadata is additive only — it increases scores but never grants access or elevates privileges; worst case is a lower-quality search result; data source is the build pipeline (trusted) |
| T-08-12 | Information Disclosure | Graph metadata exposed in responses | accept | Graph metadata only flows into scoring — it is never included in SSE messages or model context; questions_answered and topics are internal ranking signals, not sent to users or LLMs |
</threat_model>
